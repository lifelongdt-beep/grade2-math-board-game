# 초등 수학 보드게임

초등 1~6학년의 차시별 수학 문항, 조작 활동, 전자칠판 놀이와 교사용 학습 기록장입니다.

## 개발 실행

Node.js 20 이상과 pnpm 9를 설치한 뒤 저장소 폴더에서 실행합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev:local
```

표시된 주소를 브라우저에서 엽니다. `start-game.cmd`는 PATH에 설치된 Node·pnpm을 사용합니다. 특정 사용자 계정이나 Codex 설치 경로에 의존하지 않습니다. `pnpm dev`는 같은 네트워크의 기기에서도 접근할 수 있는 개발 서버입니다.

```sh
pnpm test
pnpm build
pnpm preview
```

`build`는 TypeScript 검사와 정적 사이트 생성을 수행합니다. GitHub Pages 배포는 전체 테스트가 통과한 빌드만 업로드합니다. `preview`와 GitHub Pages는 정적 사이트이므로 `/api/*` 로컬 연동 서버를 제공하지 않습니다.

## 수업·학급 설정

설정 화면의 **학급 설정**에서 학년도와 학급 이름을 저장합니다. 학급을 바꾸면 화면이 다시 열립니다. 새 기록은 학년도·학급·출석번호로 구분하며, QR에도 같은 학급 정보를 넣습니다. 1~2월의 기본 학년도는 전년도입니다.

학습 기록장은 놀이 화면의 링크 또는 `?page=records`로 엽니다. **학년도·학급**에서 한 학급을 선택해 분석합니다. 이전 버전의 기록은 **학급 미지정 · 이전 기록**에 그대로 남고 새 학급에 임의로 합치지 않습니다. 다른 학급을 볼 때 현재 학급 명단의 이름을 붙이지 않습니다. 기존 명단·보상 데이터는 처음 사용하는 기본 학급으로 한 번만 옮깁니다.

## 기록이 저장되는 곳

| 대상 | 위치 | 범위 |
| --- | --- | --- |
| 교사 학습 기록 | 교사 브라우저 IndexedDB `mathLearningLog` | 같은 사이트 주소·브라우저·프로필 |
| 휴대폰 전송 대기 답안 | 학생 브라우저 IndexedDB `mathRelayOutbox` | 연결 복구 시 자동 재전송 |
| 명단·별·카드·학급 설정 | 브라우저 localStorage | 학년도·학급별 구분 |
| 로컬 연동 서버 | 사용자 홈 `.math-board/relay-*.json` | 서버 재시작 후 복구 |
| 클라우드 연동 | 설정한 Firebase 방 | 실제 프로젝트 보안 규칙에 따름 |

사이트 주소(프로토콜·호스트·포트)가 달라지면 브라우저 저장소도 달라집니다. 저장소를 지우거나 브라우저 프로필을 바꾸기 전에 백업을 내려받으세요. 브라우저 저장을 사용할 수 없거나 파일 자동 백업이 실패하면 화면에서 안내합니다. 이 경우 창을 닫기 전에 JSON 백업을 내려받습니다.

## 백업·복구

기록 관리에서 전체 학습 기록을 JSON으로 백업하거나, 지원 브라우저에서 자동 백업 파일을 연결합니다. 브라우저를 다시 열면 파일 쓰기 권한을 다시 허용해야 할 수 있습니다. 이 백업은 **학습 기록**이며 명단·보상·전송 대기열 전체를 포함하는 브라우저 백업은 아닙니다.

복원은 지원 버전·필수 필드·학기·날짜·수치·도움말 구조를 검사합니다. 잘못된 항목이 있으면 묶음 전체를 거부하고 기존 기록을 유지합니다. 기록 삭제와 오답 PDF의 범위는 화면에서 고른 학급 및 필터를 따릅니다. 삭제 후 최근 삭제 묶음을 되돌릴 수 있습니다.

## 휴대폰 연동

답안을 먼저 기기에 보관한 후 전송하고, 서버가 수신을 확인한 뒤 대기열에서 제거합니다. 실패하면 5초 주기와 온라인 복구 시 다시 시도합니다. 같은 답안의 재전송은 같은 ID로 덮어씁니다. 교사는 클라우드 기록을 100개씩 이어 읽고, 늦게 도착한 답안도 찾도록 주기적으로 처음부터 재검사합니다.

오래된 휴대폰 탭은 이전 앱을 계속 실행할 수 있으므로 업데이트 후 새 QR로 다시 들어오세요. 설치형 PWA는 앱 자산을 캐시하지만 **기기 사이 결과 전송에는 연결이 필요합니다**. 오프라인에서 전송 대기 답안을 지우지 마세요.

로컬 서버는 배포 파일과 실행 스크립트를 같은 폴더에 두는 출판용 구조입니다. 저장소의 `scripts/` 안에는 웹앱 본문이 없습니다. 배포 파일을 준비한 폴더에서 다음 둘 중 하나를 사용합니다.

```sh
node published-server.mjs
# Windows: powershell -NoProfile -ExecutionPolicy Bypass -File published-server.ps1
```

교사는 실행 파일이 연 교사 전용 로컬 주소에서 조회·초기화를 합니다. 최초 접속의 비밀키는 URL fragment에서 로컬 세션 헤더로 전달하고 성공하면 주소에서 제거합니다. QR에는 넣지 않습니다. 직접 서버를 실행하면 콘솔의 Teacher screen 주소를 사용합니다. `MATH_TEACHER_SECRET`(32~256자)으로 운영자가 비밀키를 지정할 수도 있습니다. 세션은 실제 루프백 접속과 비밀키를 함께 확인하므로 단순 프록시나 DNS 주소 목록으로 교사 권한을 얻지 못합니다. 외부 터널의 주소를 교사 관리 주소로 사용하지 않습니다. 자세한 운영 제한은 [운영·보안 안내](docs/운영-보안-안내.md)를 확인하세요.

## 분석 결과 읽기

전체 응답 정답률, 최초 응답 정답률, 힌트 없는 최초 응답 정답률, 재도전 정답률을 구분합니다. 모둠 제안은 독립적인 최초 응답을 기준으로 하며, 쉬운 문제 5개를 맞혔다고 심화로 분류하지 않습니다. 중·상 수준의 힌트 없는 최초 응답이 5개 이상이고 그 정답률이 85% 이상일 때 심화 참고 대상으로 봅니다. 표본이 부족하면 자료 부족으로 표시합니다.

짧은 응답 시간이나 특정 오답은 교사가 원인을 확인할 단서입니다. 학습 태도나 오개념을 확정하는 진단이 아닙니다. 상 수준의 '생각 설명하기' 발문은 구두 설명을 관찰하기 위한 것으로 설명 능력을 자동 채점하지 않습니다.

## 코드 안내

- `src/data/allCurriculum.ts`: 교육과정 통합
- `src/data/questionFactory.ts`, `src/data/grade*/`: 문항·정답 생성
- `src/data/scopedQuestions.ts`: 차시 범위별 문항 구성·반복 조정
- `src/hooks/`: 문제 엔진 로딩, 원격 기록 수신, 수업 타이머
- `src/relayDelivery.ts`: 영구 전송 대기열과 재시도
- `src/data/learningLog.ts`: 교사 기록 저장·백업
- `src/data/teacherInsights.ts`: 통계·지도 제안
- `src/components/TeacherBook.tsx`: 기록장

현재 문항 엔진은 전 학년 자료를 포함해 큽니다. 교사용 PDF·그림·힌트 부품의 불필요한 선행 다운로드는 제거했지만, 학년별 문항 엔진을 완전히 분리한 것은 아닙니다. 문항 생성과 채점기는 기존 독립 검산 테스트를 유지하면서 단계적으로 분리해야 합니다.
