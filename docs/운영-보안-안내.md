# 운영·보안 적용 범위

## 코드에 반영한 보호

- 로컬 조회·초기화는 실제 루프백 접속과 HttpOnly·SameSite 세션 쿠키를 함께 확인합니다. 세션 최초 발급에는 별도 교사 비밀키가 필요하며 호스트명 DNS 결과를 신뢰하지 않습니다.
- 전달 프록시 헤더가 있는 요청에는 로컬 교사 권한을 발급하지 않습니다. 서버 재시작 시 쿠키를 다시 발급합니다.
- 상태 확인용 `/api/ping`은 기록을 반환하지 않습니다.
- 답안은 같은 ID로 중복 제거하고, 디스크 쓰기가 성공한 뒤 수신을 확인합니다. 웹 정적 파일 폴더 밖의 `.math-board`에 저장합니다.
- PowerShell 서버는 Content-Length만큼 요청을 읽어 긴 한글 답안이 잘리는 문제를 막습니다. 요청 크기와 수신 시간을 제한합니다.
- 브라우저 백업은 필수 필드·버전·날짜·수치·기본 구조를 검사하고 불완전한 묶음을 거부합니다. CSV의 수식 시작 문자를 이스케이프합니다.

이 보호는 운영체제 계정이나 같은 컴퓨터의 악성 프로그램까지 차단하는 인증 체계가 아닙니다. 학생 답안 제출 API에는 개인별 로그인 인증이 없으므로 타인의 출석번호를 선택할 가능성은 남습니다. 서버의 학습 기록 파일과 백업은 해당 컴퓨터 계정이 접근할 수 있는 자료입니다.

## Firebase: 프로젝트 관리 권한이 필요한 미적용 사항

저장소에 들어 있는 Firebase 주소는 공개 설정값입니다. 방 이름은 교사·학생 권한을 구분하는 사용자 인증 수단이 아닙니다. 이 변경은 실제 프로젝트의 보안 규칙을 읽거나 수정하지 않았으며, 안전하다고 검증한 것도 아닙니다.

정식으로 권한을 구분하려면 프로젝트 관리자가 다음 작업을 함께 해야 합니다.

1. Firebase Authentication과 교사·학생별 로그인 또는 서버가 발급하는 짧은 수명의 수업 토큰을 준비합니다.
2. 신뢰하는 서버에서 학급·수업·역할을 확인하고 방별 권한을 부여합니다. 관리자 자격증명을 웹앱이나 QR에 넣지 않습니다.
3. 교사에게만 학급 기록 읽기와 초기화를 허용하고, 학생은 본인 식별자로 본인 답안만 쓰게 합니다. 상위 경로의 광범위한 읽기·쓰기 허용 규칙도 제거해야 합니다.
4. REST 요청에 인증을 연결하고 토큰 만료·로그아웃·재시도·보안 규칙을 에뮬레이터에서 검사한 후 적용합니다. 인증 없이 동작하는 현재 앱에 규칙만 먼저 적용하면 QR 연동이 끊깁니다.
5. 방 만료·보존 기간·사용량 경보·서버 측 오래된 자료 정리 정책을 운영 기관 기준에 맞게 설정합니다. 기존 학생 자료의 삭제는 별도 검토 후 진행합니다.

이 작업은 Firebase 콘솔/관리 계정과 운영 정책 없이는 완료할 수 없습니다. 로컬 서버의 보호가 Firebase에 자동으로 적용되지는 않습니다. 연결된 Firebase를 사용하는 경우 관리자가 이 항목을 확인해야 합니다.

## 교실에서 확인할 사항

- 배포 후 전자칠판·휴대폰에서 새로 열고 긴 문제, 5명 동시 터치, 조작 활동을 확인합니다.
- 오프라인에서 몇 문제를 푼 뒤 연결을 복구하고 전송 대기 수가 0이 되는지 확인합니다.
- 교사 화면을 늦게 열어도 기록이 이어서 들어오는지 확인합니다.
- 학년도·학급 변경 후 같은 출석번호가 합쳐지지 않는지 확인합니다.
- 백업 파일을 다른 브라우저에서 복구하고 선택 범위의 오답 PDF를 실제로 인쇄해 확인합니다.
- 앱 자산 캐시와 학습 기록 저장소는 서로 다릅니다. PWA 설치만으로 기록이 다른 기기에 동기화되지는 않습니다.

상태·오류 안내에는 보조 기술이 인지할 수 있는 `status`·`alert` 역할을 사용합니다. 참고: [W3C 상태 메시지 안내](https://www.w3.org/WAI/WCAG21/Understanding/status-messages).

## 후속 준비 코드와 검사

관리자 권한이 없다는 확인에 따라 [Firebase 준비 코드](../firebase/README.md)를 추가했습니다. 운영 DB와 분리된 새 보안 경로, 교사 전용 학생 토큰 발급, 만료·보존기한 정책, 인증 전송 계층과 규칙 에뮬레이터 검사를 준비했습니다. 기존 앱의 익명 전송은 자동 전환하지 않았으며 실제 Firebase 설정은 여전히 미적용입니다. 실기기와 PDF 검증의 후속 범위는 [추가 개선·검증](추가-개선-검증.md)에 기록했습니다.
