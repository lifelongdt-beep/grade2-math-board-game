# 추가 개선과 검증 결과 (2026-11-03)

## 학년별 엔진

- 동기 검산용 `questionFactory.ts`와 실제 앱의 `questionRuntime.ts` 경로를 분리했습니다.
- 1~6학년 생성기는 `engineGrades/grade*.ts`의 동적 모듈로 준비합니다. 공통 빌더의 수준별 문제표도 등록 경로를 분리해 전 학년 생성기를 정적으로 끌어오지 않습니다.
- 선택 차시·종합 범위 및 단원 도입의 선수 학년을 먼저 준비합니다. 학년 전환 중 이전 엔진을 사용하지 않고, 누락된 엔진을 다른 학년 문제로 대체하지 않습니다.
- 기존 단일 엔진 약 3,445kB를 공통 엔진 약 404kB와 학년별 모듈로 나눴습니다. 가장 큰 학년 모듈은 2학년 약 1,097kB입니다. 생성기 결과를 바꾸지 않는 비교 검사도 추가했습니다.
- PWA 오프라인 기능을 위해 서비스 워커는 전 학년 자산을 백그라운드에서 미리 저장합니다. 분리는 전송 총량 감소나 모든 청크의 500kB 미만을 뜻하지 않습니다. 2학년 내부 생성기·공통 보조 자료의 추가 세분화는 가능합니다.

## Firebase 준비

[Firebase 준비 안내](../firebase/README.md) 참조. 관리자 권한이 없다는 확인에 따라 운영 배포 없이 별도 보안 경로·개별 학생 토큰 함수·만료 정책·인증 전송 API를 준비했습니다. 실제 규칙 에뮬레이터 5개 검사와 함수 정책 3개 검사를 통과했습니다. 운영 로그인 UI와 기존 전송 대기열의 인증 경로 전환은 관리자 환경 통합 작업으로 남습니다.

## 화면·PDF·터치 검증

- 별도 localhost:5186 시험 저장소에서 6학년 단원 도입을 시작하고 5학년 선수 문항 표시, 오답 피드백과 기록장 저장을 확인했습니다.
- 실제 화면의 오답 PDF 버튼으로 시험 1문항을 2쪽 PDF로 내려받았습니다. Poppler로 두 페이지를 렌더링하고 한글·대분수·분수 풀이가 잘리지 않는 것을 확인했습니다. 자료는 `output/qa`에 있고 저장소 업로드에서는 제외합니다.
- 390×844 휴대폰 크기의 브라우저 화면을 추가 확인합니다.
- 다섯 포인터를 동시에 누르고 역순으로 떼는 자동 회귀 검사를 추가했습니다. 이것은 실제 전자칠판의 5명 동시 터치나 프린터 출력 성공을 대신하지 않습니다. 실물 장치가 연결되지 않아 하드웨어 검증은 완료로 표시하지 않습니다.
